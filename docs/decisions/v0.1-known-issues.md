# v0.1 — Known Issues

## describe_table shows sys_dictionary view, not NowLink's curated allowlist view ✅ Fixed in v0.2

**Symptom:** `describe_table` on `incident` returned ~21 fields — only the
incident-specific fields from `sys_dictionary`. Inherited `task` fields
(`short_description`, `state`, `priority`, `assigned_to`) were missing.

**Fix:** For tables with a known allowlist in `TABLE_FIELDS`, `describe_table` now
returns the allowlist fields with mandatory status from `TABLE_MANDATORY` — not
`sys_dictionary`. This accurately reflects what NowLink actually returns. Falls back
to `sys_dictionary` only for unknown tables.

---

## describe_table misses inherited fields — breaks create validation ✅ Fixed in v0.2

**Symptom:** `create_record` called `describe_table` to get mandatory fields before
writing. Since `sys_dictionary` misses inherited fields, `short_description` on
`incident` was never flagged as mandatory — validation silently passed without it.

**Fix:** Added `TABLE_MANDATORY` to `shaper.py` — an authoritative dict of mandatory
fields per table including inherited ones. `create_record` uses this for known tables
instead of querying `sys_dictionary`.

---

## Required roles for nowlink.dev not obvious from ServiceNow documentation

**Symptom:** `rest_service` alone is not enough to query ITSM tables or `sys_dictionary`.
Took trial and error to identify the full required role set.

**Roles required and why:**
- `rest_service` — baseline for OAuth token and API access
- `itil` — read access to incident, problem, change, task and related ITSM tables
- `personalize_dictionary` — read access to `sys_dictionary` (needed for `describe_table`)

**Fix planned (v0.3):** Document in README. Add `nowlink check-roles` CLI command that
verifies the integration user has all required roles.
