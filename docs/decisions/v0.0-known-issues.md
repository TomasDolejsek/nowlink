# v0.0 — Known Issues

## verify=False on all httpx calls

**Symptom:** SSL certificate verification is disabled on every HTTP call.

**Root cause:** PDI uses certificates that httpx cannot verify on Windows. `certifi` was
already installed but didn't resolve it. `verify=False` was added as a quick fix.

**Impact:** Insecure — not acceptable to ship to PyPI.

**Fix planned:** Add a `NOWLINK_SSL_VERIFY` option to `.env` defaulting to `true`,
with a `--no-verify` flag for `nowlink init` that sets it to `false` for PDI use.

---

## Hardcoded venv path in `nowlink connect`

**Symptom:** `nowlink connect` wrote the absolute path `C:\Tom\Programming\08_NowLink\.venv\Scripts\nowlink.exe`
to the Claude Desktop config. Breaks on any other machine.

**Root cause:** Path was hardcoded during v0.0 development.

**Fix (v0.1):** Auto-detect the executable path using `sys.executable` — the nowlink
executable sits in the same `Scripts/` directory as the Python interpreter. ✅ Done in v0.1.

---

## No token refresh using refresh_token

**Symptom:** On token expiry, NowLink fetches a completely new token using username +
password instead of using the refresh_token from the previous response.

**Root cause:** Simpler to implement for v0.0. Refresh token flow requires storing and
rotating the refresh token separately.

**Impact:** Minor — works correctly, just slightly less efficient. Full re-auth every
30 minutes instead of a lightweight refresh.

**Fix planned:** Implement proper refresh_token flow in v0.2.

---

## No logging

**Symptom:** No record of what tool calls Claude made, what parameters were used, or
what errors occurred.

**Impact:** Can't debug tool calls after the fact.

**Fix (v0.1):** Added `~/.nowlink/logs/YYYY-MM-DD.log` via `logger.py`. ✅ Done in v0.1.
